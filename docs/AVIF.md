# AVIF representation support

The bounded still-image path uses libavif 1.4.2 and libaom 3.13.1 (BSD-2-Clause) for opaque eight-bit encoding. Direct quality [0,100] is rounded and clamped to native quality [1,100]. Score search candidates that round to an already-encoded native quality reuse that encode and score instead of repeating them; PNG palette candidates reuse results the same way by palette size. Effort fast, balanced, best maps to native speed 8, 6, 6. Encoding uses one thread. Cancellation is checked before encoding; libaom cannot be interrupted during encoding. Output uses 8-bit 4:4:4 full-range BT.601 matrix with BT.709 primaries and sRGB transfer, signaled by a standard nclx property.

Decoding uses a bounded unsafe shim over rav1d 1.1.0 (BSD-2-Clause, bitdepth_8, vendored with its upstream ARM and x86 assembly enabled) with AV1 film grain applied. Container color signaling is checked when present. Otherwise color is taken from the decoded AV1 sequence header. Eight-bit SDR sRGB signaling is required. Full and limited YUV ranges have explicit conversion paths, and decoded RGB carries full-range identity-matrix CICP. An independent dav1d test decodes the pinned fixtures and compares samples.

Alpha, monochrome, grids, animation, high precision, container rotation or mirroring, clean aperture, non-square pixel aspect ratios, HDR light/mastering/gain-map metadata, and premultiplied alpha are refused. Header inspection reports container grid, rotation, mirror, pixel aspect and HDR fields independently of pixel decode, including light and mastering metadata in a non-grid AV1 bitstream. A single item containing multiple temporal frames is refused after draining available frames; flushing the decoder discards them and cannot establish a still-image guarantee. PNG and WebP provide verified alpha paths.

Encoding embeds EXIF only. Common sRGB ICC sources therefore convert to NCLX-signaled sRGB AVIF without an ICC profile, and candidates whose ICC or XMP survive only via the container are refused. Lossless AVIF, alpha and grayscale encoding are refused. Direct native grayscale saves nothing over the refused path.

The unaccepted alpha experiment is preserved at local branch `campaign/s5-alpha-probe`, commit `a4d2fb5`. Its exact alpha test failed with the selected published stack: alpha 0 becomes 1 through independent dav1d, including the explicit lossless flag. Those failures are implementation limitations, not unavailable-environment proofs. Retry only after a dependency correction or a newly established cause passes the original sample assertions without tolerance changes. Do not enable AVIF alpha merely because an encoder accepts RGBA.

The decoder shim exists because rav1d's raw dav1d-style API is the only permissive pure-Rust AV1 decode path; it bounds allocations, drains and copies planes out of rav1d-owned memory, and never exposes rav1d types across the boundary. Replacing it requires independent external matrix and range cases, including the regressions linked above.

The ISOBMFF/AVIF container reader is implemented in-tree at `src/still/avif_container.rs`, written from ISO/IEC 14496-12, ISO/IEC 23008-12 and the AV1 sequence-header spec (bounded, dependency-free, corruption-hardened, cancellation-aware). zenavif-serialize 0.1.4 retains BSD-3-Clause (development-only fixture tool). rav1d is the vendored snapshot described in [VENDOR.md](VENDOR.md); its assembler features are enabled, runtime CPU detection selects the vector path, and the decoded eight-bit samples are byte-identical to the previous pure-Rust build.
