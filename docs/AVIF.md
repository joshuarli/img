# AVIF representation support

The bounded still-image path uses zenavif 0.1.6 and zenravif 0.1.3 with zenrav1e 0.1.4 for opaque eight-bit encoding. Direct quality [0,100] maps to native quality [1,99]. The highest direct control avoids implying a strict lossless mode. Effort fast, balanced, best maps to native speed 10, 8, 6. Codec threads are disabled.

Decoding uses rav1d-safe 0.5.7 plane access with explicit RGB identity and YUV matrix handling. Container color signaling is checked when present. Otherwise color is taken from the decoded AV1 sequence header. Eight-bit SDR sRGB signaling is required. Full and limited YUV ranges have explicit conversion paths. The independent dav1d test currently covers the encoder-produced BT.601 case; it does not establish coverage of external identity, BT.709 or both range variants.

Alpha, monochrome, grids, animation, high precision, container rotation or mirroring, clean aperture, non-square pixel aspect ratios, container HDR light/mastering/gain-map metadata, and premultiplied alpha are refused. Header inspection reports container grid, rotation, mirror, pixel aspect and HDR fields independently of pixel decode. AV1 bitstream-only light metadata currently escapes both refusal and inspection reporting ([RIMG-10](../TODO.md#rimg-10--p2--av1-bitstream-hdr-metadata-escapes-avif-validation-and-inspection)). A single item containing multiple temporal frames is refused after draining available frames; flushing the decoder discards them and cannot establish a still-image guarantee. PNG and WebP provide verified alpha paths.

Two known decode-boundary defects affect accepted images. Film grain is disabled, so active-grain AVIFs silently lose displayed detail even in a lossless conversion ([RIMG-2](../TODO.md#rimg-2--p1--lossless-conversion-silently-removes-avif-film-grain)). Decoded RGB retains the source YUV CICP matrix, causing invalid PNG signaling and failed lossless AVIF-to-PNG conversion ([RIMG-5](../TODO.md#rimg-5--p2--avif-to-png-conversion-retains-a-yuv-matrix-for-rgb-samples)).

The unaccepted alpha experiment is preserved at local branch `campaign/s5-alpha-probe`, commit `a4d2fb5`. Its exact alpha test fails with the selected published stack: alpha 0 becomes 1 through independent dav1d, including the explicit lossless flag. The managed Rust decoder also disagrees with the independent alpha plane. Those failures are implementation limitations, not unavailable-environment proofs. Retry only after a dependency correction or a newly established cause passes the original sample assertions without tolerance changes. Do not enable AVIF alpha merely because an encoder accepts RGBA.

The direct managed plane adapter avoids the published high-level decoder's fallback of the RGB identity matrix to BT.601. Replacing this adapter requires independent external matrix and range cases, including the regressions linked above.

zenavif, zenravif, zenrav1e and rav1d-safe select AGPL-3.0-only. Preserve their upstream notices, including zenrav1e PATENTS; no commercial license is assumed. zenavif-parse 0.6.2 retains MPL-2.0 and zenavif-serialize 0.1.4 retains BSD-3-Clause. Assembly and unsafe C FFI features of rav1d-safe are disabled. Its build script emits Rust cfg values in this configuration. Third-party assembler code is not selected.
