# Permissive pure-Rust codec audit (2026-11-13) — history

> **Archived 2026-11-18.** The pure-Rust requirement for JPEG, PNG and AVIF was
> withdrawn; permissive native code is authorized. The active status is
> [CODECS.md](CODECS.md). This survey is kept as evidence.

## Scope and evidence standard

Goal: make `img`/[`joshuarli/img`](https://github.com/joshuarli/img) genuinely usable and distributable with a **permissively licensed pure-Rust normal/build dependency closure**, preserving the existing still-image correctness, color, metadata, security, static Linux builds and measured quality/performance. This is a **candidate survey, not an SOTA certificate**: current public claims are author-reported unless explicitly independently reproduced in this repository. No new candidate has been benchmarked here yet. Select by evidence, not crate names, license badges, identical quality knobs, or synthetic-only timing.

Current provenance: [`docs/PROVENANCE.md`](PROVENANCE.md) and [`Cargo.toml`](../Cargo.toml) pin AGPL `zenjpeg`, `zenwebp`, `zenpng`, `zenavif`, transitively `zenravif`/`zenrav1e`, `rav1d-safe`, `zenflate` and `zenquant`, plus GPLv3 `imagequant`. Not every `zen*` crate is AGPL: `zencodec`, `zenpixels`, and `zenyuv` have permissive license choices. `zenavif-parse` is MPL-2.0 (weak copyleft, not permissive, but not AGPL); `zenavif-serialize` is BSD-3-Clause. `moxcms`, `fast-ssim2`, `png`, `fdeflate`, `libm` etc. need no automatic replacement on AGPL grounds.

**Do not conclude the binary has become permissive when one crate is replaced.** Produce fresh `cargo tree -e normal,build`, `cargo tree -i <package>`, fresh target-specific locked SBOM/license inventory, fresh static-linkage check and source-archive notice audit after each cutover. Do not mistake an optional *declared* dependency for a *selected* dependency, or a C build-dependency crate for executed C compilation; test a clean target with native tools withheld. No native C/FFI codec implementations in shipping artifacts. Rust `unsafe` and assembly are independent review dimensions.

## Important exclusions and traps

1. [oxipng](https://github.com/oxipng/oxipng) is MIT-licensed Rust **but its current `Cargo.toml` has an unconditional `libdeflater` dependency**, whose implementation uses C. Disabling `zopfli`/default features is **not** enough to make the stock tool a pure-Rust shipping backend. Use its filter search strategy/performance as a permissible *reference*, not production, unless it is correctly ported/reworked and independently validated.
2. [rivet-webp](https://github.com/safewords/rivet-webp) is technically interesting but its `LICENSE.md` explicitly calls itself **source-available, not open source**, with use-dependent commercial attribution. Do not import it into this permissive-only product.
3. `quantette` is not an RGBA replacement. Never drop transparency for a benchmark win.
4. `avif-decode` does not solve ICC/HDR. `rav1d` and `ravif` can activate native assembly by default. Even all-Rust source can bring `cc`/NASM as build dependencies, so confirm **actual** tool invocations under the intended feature configuration.
5. `zenzop` is permissive by **crate** license but its default **dependency closure is not**. Verify feature unification in the caller.
6. `mozjpeg-rs` comes from Imazen but is **not AGPL**. Do not reject by owner prefix; do not assume its unreleased main-version is available on crates.io.
7. No claimed SOTA winner has yet passed this repo's **matched-quality and matched-resource** comparisons. Author-provided speed claims, clone popularity and synthetic ratios are hypotheses only.
8. For strict no-copyleft rather than only no-AGPL, review every MPL-2.0 (including `zenavif-parse`) and GPL-selected dependency before release, not just the top-level crate.

## Experimental campaign — independently prove or reject replacements

**E0. Exact dependency truth.** Freeze baseline source and `Cargo.lock`, dump `cargo tree -e normal,build` and `cargo metadata` for macOS ARM64, Linux ARM64 musl, Linux x86_64 musl, both default and `build-binary`. Produce a verified license / asm / runtime native-code report with version, selected features, executed build tools. Keep `src/operations/quantize` visible even though it is legacy library API.

**E1. Harness first.** Use a **single** codec-agnostic evaluation driver (existing `tests/`, `BENCHMARKS.md` and benchmark corpus). Inputs must include CLIC/real licensed photographs, gradients, screenshots/text, line art, grain/noise, opaque/transparent RGBA, edge alpha, grayscale, ICC/EXIF/XMP, 16-bit and known-invalid/truncated files. Serialize input hashes/provenance, output checksums and refusal reasons. Match quality by **actual independently decoded SSIMULACRA2 score** (80/90/95 plus exact lossless), not equal `-q`, and compare bytes/encode/decode median+p95/RSS/allocations/build time. Capture CPU/target/toolchain/config/repetitions; use interleaved A/B on immutable release builds, no emulated speed claims. Comparator failures must be retained, not removed from denominators.

**E2. Parallel experiments with separate worktrees:** 
- JPEG lane: `mozjpeg-rs` (actual released version) + `zune-jpeg` vs zenjpeg at exact `img` target score; include `rusty_jpeg`/jpeg-encoder controls. Validate progressive, gray, ICC/EXIF, no hidden format degradation.
- PNG lane: current `png` vs `rusty_png` on exact 8/16-bit + ICC/alpha preservation; evaluate zlib-rs, zopfli and zenzop **with audited features**, filter search and content-adaptive effort.
- Palette lane: `quantizr` RGBA vs `imagequant` + zenquant; `quantette` opaque RGB only. Evaluate visually transparent edges, dither/color metrics and indexed PNG byte size, under exact alpha policy.
- AVIF encoder lane: `ravif/rav1e`, `rusty_av1e`, `oxideav-avif` at *8-bit SDR* and matched scores; inspect alpha, metadata, color and exact output validity.
- AVIF decoder lane: `avif-decode/rav1d`, no-asm `rusty_av1d`, `oxideav-avif`; test strictly supported containers and untrusted inputs; no default ASM or C tool execution in shipping. Account for ICC/HDR/HEIF omission explicitly.
- WebP lane: execute the separate [WEBP-HILLCLIMB](roadmap.md#campaign-webp-hillclimb) campaign; **do not duplicate** its codec fork.

**E3. Migration in gated cuts.** Integrate codec-specific private adapters in `src/still/`, never refactor unrelated public contracts to fit vendor APIs. Preserve `zencodec`/zenpixels as long as permissive. Every cut must pass the independent decoder tests, exact metadata/color/alpha/hidden RGB proof, bounded allocations and cancellation, `make baseline-check`, `make decoder-reference-check`, `make benchmark-verify`, `make pure-rust-build-check`, target builds and test release artifacts. Revert a candidate failing correctness; keep measured tradeoffs explicit. Retire AGPL/GPL dependencies only after removal of **all normal/build paths** to them.

**E4. Completion criteria.** A truly permissive release has (a) zero AGPL/GPL and, if all-permissive is mandatory, zero MPL runtime/source obligations, with proven feature graph and notices; (b) zero executed third-party native codec build steps; (c) preserved accepted formats/metadata/precision and independent score/quality; (d) no significant unacknowledged Pareto regressions; (e) updated `docs/PROVENANCE.md`, `README.md`, `BENCHMARKS.md`, `Cargo.lock`, packaging/source bundle and CI. Never claim this outcome from an unused imported source directory.

This audit intentionally **does not** modify production dependencies or accept any performance ranking without reproducible runs.
